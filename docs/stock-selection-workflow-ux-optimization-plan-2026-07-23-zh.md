# 面向选股流程的产品收敛与新手体验优化方案

日期：2026-07-23  
范围：Personal Quant Workbench（A 股与美股日线、收盘后决策工作台）

## 1. 结论

应用不缺功能，缺的是一条用户不必学习产品结构、也能每天重复执行的工作路径。

建议将产品从“研究工具集合”收敛为以下四步：

```text
判断今天能不能做
        ↓
发现值得研究的候选
        ↓
验证候选并写入观察/持仓计划
        ↓
跟踪结果、处理风险、复盘模型
```

首页只回答“今天下一步是什么”；模型评测、数据状态、任务中心、社交、AI 问答等能力保留，但不再作为新手的主导航。这样既不删掉已有积累，也不会让页面显得像后台管理系统。

产品定位保持不变：**为个人交易者提供收盘后、日线级别的高质量选股与复盘助手，不提供自动下单或确定性收益承诺。**

## 2. 当前问题

### 2.1 导航按系统功能分类，而非按交易任务分类

现有导航同时平铺首页、自选、持仓、重点监控、模型选股、市场概览、社交信号、AI 问答、复盘心得、任务中心、数据状态、设置。它对熟悉系统的人完整，但对新用户有三个负担：

- 不知道应该从哪一页开始；
- 不知道“模型结果”“自选”“持仓”“重点监控”之间的先后关系；
- 容易误把数据、任务和模型能力当成每日必须操作。

### 2.2 首页承担了过多角色

首页同时展示数据新鲜度、模型训练、预计算、日报、候选、自选、持仓、新闻、任务等信息。每一项单独有价值，但同屏展示会稀释最重要的动作：今天是进攻、观察还是防守；应该优先看哪些候选；已有持仓需要处理什么。

### 2.3 研究能力与执行能力没有明确分层

模型赛马、OOS 评测、市场状态、任务运行、数据源健康是保证质量的“系统能力”；它们应在异常或需要审计时出现，而非持续占用交易决策的注意力。

### 2.4 A 股和美股需共享方法、分开上下文

两类市场都应遵循同一套四步流程，但交易日、风险规则、数据新鲜度、候选池和模型表现均不能混淆。界面需要提供明确的市场切换与分区，而非在一张结果表中混排。

## 3. 目标信息架构

### 3.1 主导航：五个入口，按每天的使用顺序排列

| 入口 | 用户要回答的问题 | 主要页面/已有能力 |
|---|---|---|
| 今日决策 | 今天应进攻、观察还是防守？ | 精简后的 Dashboard |
| 市场判断 | A 股/美股当前是什么市场状态？ | 市场概览、热力、盘前/盘中/盘后快照 |
| 发现候选 | 今天有哪些可研究的候选？ | 模型选股、模板、全市场候选 |
| 自选与执行 | 哪些候选进入观察，触发条件是什么？ | 自选股、新闻风险、重点监控 |
| 持仓与复盘 | 已有仓位如何处理，模型是否值得继续信任？ | 持仓、日报、周复盘、历史动作 |

“重点监控”并入“自选与执行”，而不是独立一级模块；“AI 日报”并入“持仓与复盘”，成为输出物而不是入口。

### 3.2 工具区：保留能力，默认折叠

侧栏底部增加一个默认折叠的“研究与系统工具”区域：

- 模型评测与冠军/挑战者赛马；
- 社交信号与 AI 问答；
- 复盘心得；
- 任务中心；
- 数据健康与数据源；
- 设置。

当用户进入其中任一页面时，工具区自动展开并高亮对应入口。这样不会损失已有功能，也避免把复杂性转嫁给新手。

### 3.3 A 股 / 美股的表达规则

- 顶部提供常驻市场切换：`A 股`、`美股`、`全市场（只用于总览）`；默认记住用户上一次选择。
- 市场判断、候选列表、自选列表、持仓列表均按当前市场展示；全市场仅显示汇总卡片和明确分栏，禁止混排股票明细。
- 每个市场页都显示该市场的“最近交易日、行情状态、模型状态、可执行候选数”。
- 任何候选、风险、命中率标签必须带市场标记，防止使用者用 A 股口径误读美股结果，反之亦然。

## 4. 核心页面重构

### 4.1 今日决策：只呈现今日需要完成的事

首页首屏按以下优先级排列：

1. **今日市场许可**：用一句人话给出“可小仓试错 / 仅观察 / 优先降风险”，同时展示关键依据和置信度；
2. **下一步按钮**：根据市场许可，主按钮指向“开始选股”或“查看持仓风险”；
3. **四步进度条**：市场已判断、候选已生成、自选已复核、持仓已复盘；每一步可进入对应页面；
4. **行动清单**：最多各三条“可执行候选”“只观察”“需要减风险”，点击进入个股详情；
5. **轻量状态条**：行情、模型、快照是否可用；只有异常时展开失败原因与“前往任务中心”。

从首页移出或折叠：完整 Job 列表、历史模型指标、数据湖详情、新闻覆盖诊断、所有候选列表、所有持仓列表。它们仍在二级页可查。

### 4.2 市场判断：先给结论，再给证据

页面结构固定为：

1. 当前市场状态与仓位建议；
2. 宽度、波动、强弱行业、风险标签四个核心证据；
3. 按交易时段显示盘前计划、盘中变化或盘后复盘；
4. “去发现候选”按钮。

保留热力图、概念追踪等研究组件，但移至“展开市场细节”。不让首屏变成图表墙。

### 4.3 发现候选：把模型转换为可验证的名单

候选页默认采用“决策模式”，不是“模型配置模式”：

- 先选市场，再选意图：`趋势延续`、`回踩确认`、`防守观察`；
- 默认展示预计算、已通过交易治理的候选，且按“可执行 / 仅观察 / 不可执行”分组；
- 每只股票保留最少决策字段：信号、入场触发、失效条件、风险、模型置信度、市场状态匹配度；
- 主操作只有“加入自选”和“查看详情”；
- 模型、因子、组合、全市场模板、快照比较等设置移入“高级研究”，供熟练用户展开。

候选页必须明确展示：模型只生成研究优先级，不等于买入指令；模型处于观察状态或 OOS 样本不足时，不能以“推荐”措辞呈现。

### 4.4 自选与执行：让观察池成为小而清晰的行动队列

自选股默认分为四组：

- 主攻：已满足大部分条件、等待精确触发；
- 观察：逻辑成立但条件未齐；
- 风险：出现新闻、价格或基本面风险，需要优先复核；
- 失效/归档：失效条件满足或长期未触发，保留审计记录但不干扰日常列表。

每行只显示状态、触发条件、失效条件、最近变化和下一步。新闻机会/风险在此处作为“验证证据”出现，不再独立占据首页。

### 4.5 持仓与复盘：风险优先而非资产清单优先

持仓首屏顺序应为：

1. 今天需要处理的仓位（减仓、退出、复核）；
2. 组合暴露和集中度；
3. 正常跟踪的持仓；
4. AI 日报、周复盘和已执行动作的历史。

日报应被设计成“一次复盘的可读输出”：市场结论、持仓动作、明日观察、风险提示与模型备注；技术原始数据放在可展开证据里。

## 5. 新手引导

新用户首次进入首页，展示一个可关闭的短引导，不使用多步弹窗打断操作：

```text
每天收盘后，只需完成四件事：
1. 看市场许可；2. 从候选中选 3–8 只进自选；
3. 为每只写清触发与失效条件；4. 复核持仓与日报。
```

配套提供：

- 示例模式：显示说明性演示数据或空状态指引，不把模拟结果当真实信号；
- 每个核心页顶部的一句“本页用途”和一个“下一步”；
- 术语采用业务语言，例如“可执行候选”“只观察”“失效条件”，避免让新手先理解 OOS、快照、赛马等术语；
- 在个股详情中统一解释信号、风险、模型状态、行情日期的来源和更新时间。

## 6. 模块取舍原则

| 类型 | 处理方式 | 代表模块 |
|---|---|---|
| 每日决策必需 | 一级入口、首屏可见 | 市场、候选、自选、持仓、复盘 |
| 每日必要但不需手工操作 | 首页仅显示异常 | 行情刷新、模型刷新、候选预计算、日报任务 |
| 高级研究 | 折叠到工具区 | 模型评测、因子实验、模型赛马、社交验证 |
| 系统维护 | 工具区，异常才引导进入 | 任务中心、数据状态、快照保留、基础面同步 |
| 低频偏好设置 | 工具区末尾 | 通知、语言、系统设置 |

原则不是删除数据和模型能力，而是让它们只在用户需要判断、排错或研究时出现。

## 7. 实施顺序

### 第一阶段：信息架构收敛（低风险）

1. 重构全局侧栏为五个主入口 + 一个折叠工具区；
2. 保持所有现有 URL 有效，旧入口跳转或在工具区保留；
3. 首页删除重复入口和常态化运维细节，加入四步进度与异常状态条；
4. 在所有主要页面接入 A 股 / 美股一致的市场切换和新鲜度标记。

### 第二阶段：核心页按流程改版（中风险）

1. 候选页分成“决策模式 / 高级研究”；
2. 自选股实现四组观察池与触发/失效条件；
3. 持仓页实现风险优先视图和动作闭环；
4. 日报和周复盘归入复盘工作区。

### 第三阶段：新手体验与度量（持续）

1. 加入首用引导、空状态与术语解释；
2. 记录匿名产品事件：首次选股完成率、候选加入自选率、持仓复核完成率、工具区使用率；
3. 根据事件和用户反馈继续删减重复卡片、合并入口。

## 8. 数据与可靠性前提

界面收敛不能掩盖数据问题。每个市场必须继续展示以下真实状态：

- 行情最近交易日与预期交易日的差异；
- 模型信号生成时间、训练版本和启用状态；
- 候选快照是否来自当前行情；
- 当日必要 Job 的成功、运行中或失败状态；
- 缺失行情是否已被识别为停牌、非交易日、数据源失败或待补齐。

异常应通过首页状态条和候选页提示直接影响操作许可：行情或模型过期时，候选降级为“不可用于今日决策”，而不是继续显示为正常推荐。

## 9. 验收标准

### 体验验收

- 新用户从首页进入后，能在 30 秒内理解当天应从哪里开始；
- 不查看工具区，也能完成“市场判断 → 候选 → 加入自选 → 持仓复核”四步；
- 侧栏首层不超过五个日常入口，系统和研究入口默认不展开；
- A 股和美股的候选、数据状态、模型状态不会在明细层混排；
- 首页首屏不出现完整 Job 表、完整模型评测表或重复的导航卡。

### 功能验收

- 现有核心 URL、历史 Job、模型评测、AI 日报、社交信号、设置功能仍可访问；
- 行情、模型或快照异常时，首页和候选页均显示不可用于决策的原因和排查入口；
- 候选可从模型页加入自选，持仓自动纳入复核，动作能在日报/历史中追溯；
- A 股和美股分别显示各自的最新交易日、刷新状态与模型状态；
- 高级模型处于 observation/unverified 状态时，候选页不会以可执行推荐展示。

### 技术验收

- 路由兼容：旧链接继续可用；
- 响应性能：首页只读取预计算摘要，不新增大范围行情扫描；
- 移动端：主导航可折叠，核心动作不依赖宽表；
- 可访问性：市场切换、折叠工具区、状态标签均可通过键盘访问，颜色外另有文字状态。

## 10. 首轮改版的明确边界

首轮不改变选股模型、交易规则、数据源或自动任务调度；目标仅为重构信息架构、页面优先级与新手路径。模型胜率提升、策略优化、数据补齐仍按既有评测和质量链路独立推进，避免把“界面更清晰”误解为“收益被承诺”。
