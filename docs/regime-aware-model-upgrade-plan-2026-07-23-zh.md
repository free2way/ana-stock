# 市场状态感知的选股模型升级开发方案

日期：2026-07-23  
适用范围：A 股、美股的 LightGBM 选股、模型评测、候选筛选和风险闸门

## 1. 目标与边界

目标不是承诺提高收益，而是建立一套可验证的模型迭代机制：只有当新模型在严格滚动样本外、扣除成本后，持续优于当前基线时，才允许进入候选选股链路。

当前 LightGBM 多因子模型继续作为基线，不直接下线。近期评测显示其 5 日成本后表现偏弱，因此在新体系验收前，LightGBM 候选只能作为观察或与其他约束叠加后的输入，不能被单独解释为买入建议。

不纳入本期范围：自动实盘下单、收益保证、使用未核验的新闻或行情数据覆盖历史记录。

## 2. 当前问题

1. 现有模型的历史评测尚有非严格样本外样本，不能作为最终胜率。
2. 同一模型在风险偏好、暴跌、高波动和反弹失败行情下使用相同阈值，容易在不适合的市场环境产生错误候选。
3. 目标主要是收益排序，尚未把交易成本、跳空、流动性和持有期内最大回撤共同作为启用门槛。
4. 美股存在退市、拆股和非普通股混入问题；公司行为或行情异常会污染训练和评测。

## 3. 设计原则

```mermaid
flowchart LR
    A[行情与公司行为校验] --> B[市场状态识别]
    B --> C[候选模型赛马]
    C --> D[成本后滚动样本外评测]
    D --> E{达到启用门槛?}
    E -->|是| F[市场状态下的模型权重/候选]
    E -->|否| G[继续观察或下线]
    F --> H[流动性/跳空/回撤风控]
    H --> I[筛选器、日报与任务中心]
```

- 市场状态优先于模型分数：`BLOCK` 时不因高分绕过风险闸门。
- 以成本后净收益、最大回撤和稳定性共同判断，不只看命中率。
- 所有模型、数据版本、市场状态和评测结果都必须落库、可追溯。
- 对拆股、退市、停牌、低流动性、重复行情分区建立明确排除或降级记录。

## 4. 模型架构

### 4.1 基线与候选模型

| 层级 | 模型 | 用途 | 是否直接用于交易候选 |
|---|---|---|---|
| 基线 | LightGBM 多因子排序 | 保留现有可解释、训练快速的基线 | 仅通过市场状态与风险门槛后 |
| 对照 A | XGBoost 排序/分类 | 检验另一类正则化树模型是否更稳 | 否，先进入赛马 |
| 对照 B | CatBoost 排序/分类 | 处理缺失值、类别特征和非线性互动 | 否，先进入赛马 |
| 元标签 | 交易可执行性分类器 | 预测高分候选是否应跳过 | 是，作为 LightGBM/XGBoost/CatBoost 的二次门槛 |
| 状态模型 | 市场状态分类器 | 输出 risk-on、watchful、defensive 与波动/广度标签 | 是，控制权重与仓位上限 |

第一阶段不引入 LSTM/Transformer 作为主模型。复杂时序模型应在树模型赛马、数据质量和严格样本外评测成熟后，再以独立实验方式接入。

### 4.2 市场状态维度

复用已有 `market_regime_snapshot`，并补充以下特征：

- 市场广度：上涨比例、跌幅中位数、接近 20 日低点比例；
- 波动：截面波动、指数波动、尾部下跌比例；
- 趋势：指数及市场等权收益相对 MA5/MA20；
- 流动性：成交额、成交量、涨跌停或异常跳空代理；
- 风险状态：`risk_on`、`watchful`、`defensive`、`high_volatility`、`high_dispersion`、`rebound_failed`。

状态输出规则：

| 市场状态 | 新开仓规则 | 模型使用 |
|---|---|---|
| `risk_on` | 允许，但仍受流动性与回撤限制 | 使用经赛马胜出的模型/组合 |
| `watchful` | 小仓、只接受高置信度与低回撤候选 | 提高阈值，优先元标签通过项 |
| `high_volatility` / `high_dispersion` | 不追高，缩小候选 | 只保留低波动、强流动性候选 |
| `defensive` / `rebound_failed` | 禁止新增仓位 | 只展示观察名单，不输出正常 BUY |

## 5. 训练与样本定义

### 5.1 目标变量

每个持有期独立训练或独立评测：1、3、5、10、20 个交易日。

主目标不使用单纯未来收益，改为组合目标：

```text
可交易标签 =
  未来净收益 > 成本阈值
  且持有期最大回撤 > -最大容忍回撤
  且无异常跳空/流动性失效
```

模型仍可输出连续排序分数；元标签决定该分数是否可执行。

### 5.2 样本隔离

- 训练、验证、测试按交易日期前推，禁止随机切分。
- 使用 purged walk-forward：训练窗口结束与测试窗口之间留出最大持有期的隔离期，防止标签泄漏。
- 每次 Run 固定记录：特征版本、股票池版本、行情日期、公司行为版本、训练/验证/测试日期和市场状态版本。
- 退市、拆股异常、重复冲突行情、非普通股和不满足流动性要求的样本必须记录排除原因。

## 6. 统一评测与模型赛马

### 6.1 指标

每个模型 × 市场 × 市场状态 × 持有期至少保存：

- 样本数、覆盖交易日、严格样本外比例；
- 成本后命中率及置信区间；
- 平均/中位数净收益、基准超额收益；
- 平均回撤、最大回撤、收益回撤比、盈亏比；
- 换手、预估交易成本、跳空阻断率、低流动性阻断率；
- 公司行为/异常价格排除数。

### 6.2 启用门槛

新模型进入生产候选链路需同时满足：

1. 连续至少 20 个交易日的滚动样本外结果；
2. 每个目标市场、目标状态、目标持有期样本数达到预设下限；
3. 成本后平均收益高于 LightGBM 基线，且置信区间不完全落在零以下；
4. 最大回撤不差于基线，换手和成本未显著恶化；
5. 在 `defensive` 状态不扩大风险暴露；
6. 数据质量门禁为 ready，或有明确、可审计的人工例外。

任何一项不满足，状态为 `observation`，不可进入日报的正常买入排序。

### 6.3 权重与降级

不以固定权重叠加模型。每日读取最近滚动窗口的状态分层成绩：

```text
模型权重 = 状态内的风险调整净收益 × 置信度 × 数据质量系数
```

- 样本不足时权重为 0，不做推断补全；
- 评测连续恶化时自动降为 `observation`；
- 任一市场进入 `BLOCK` 时，所有模型权重仅供观察，不产生买入动作。

## 7. 开发阶段

### Phase 1：评测口径收紧（优先）

1. 为 `model_evaluations` 增加严格样本外标记、隔离期、基准收益和股票池版本。
2. 修复当前预测日期与训练区间重叠导致的非严格样本外评测。
3. 增加异常公司行为、退市、停牌、价格跳变和重复行情质量标签。
4. 模型评测页明确区分“观察样本”“严格样本外”和“可启用”。

验收：所有展示的胜率都能说明样本外状态、成本假设和市场状态覆盖率。

### Phase 2：状态模型与元标签

1. 将现有风险快照标准化为训练特征及日级状态表。
2. 为 LightGBM 候选建立可执行性元标签。
3. 将状态门控接入候选、日报和仓位建议。

验收：`defensive` 状态下无正常 BUY；`watchful` 状态的候选数、仓位提示和风险理由可追溯。

### Phase 3：XGBoost / CatBoost 赛马

1. 共享特征、股票池、训练切分与成本模型，确保公平对比。
2. 生成独立 `ModelRun`、预测和结构化评测记录。
3. 在每个市场状态中比较模型，不只比较总平均值。

验收：任务中心和模型评测页可直接查看三模型的状态分层结果及启用状态。

### Phase 4：受控集成

1. 对通过门槛的模型启用状态内权重；其余保持观察。
2. 将模型选择理由写入候选快照和 AI 日报。
3. 建立连续失效告警和一键回退到 LightGBM 基线的机制。

验收：生产切换可回滚；任何候选均可追溯到具体模型、状态、评测和数据版本。

## 8. 任务与页面改造

- 新增任务：`train_xgboost_signals`、`train_catboost_signals`、`train_meta_label`、`run_walk_forward_evaluation`、`model_champion_challenger`。
- 任务中心按 A 股/美股分别展示训练、评测、状态快照和赛马结果。
- 模型评测页增加：严格样本外标识、状态筛选、成本开关、基准对比、启用/观察/下线状态。
- 候选页显示：模型来源、当前市场状态、元标签结果、风险阻断原因和最近评测摘要。

## 9. 风险控制与停止条件

- 不因为历史命中率提升而放松数据质量门禁。
- 不以单日或单周表现切换主模型。
- 未达到最小样本数、市场状态覆盖不足、成本后收益为负或最大回撤恶化时，停止扩大使用范围。
- 人工批准的行情例外必须独立计数，不能混入数据源确认的 `no_trade`。

## 10. 首次实施建议

先实施 Phase 1 与 Phase 2，积累至少 20 个交易日严格样本外记录后，再开始 XGBoost/CatBoost 赛马。当前 LightGBM 的近期表现不足以支持直接替换，更不适合直接引入复杂深度模型。
