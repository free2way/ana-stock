# 应用 Review（2026-07-22）

## 结论

应用的核心方向是正确的：盘后刷新行情 → 训练/计算模型 → 预计算候选 → 风险检查 → 生成日报。但之前“任务完成”与“数据可用”没有完全绑定，导致更新时间看起来很新，个别股票或模型输入却可能落后。

## 本次已修复

1. **行情湖未来日期保护**
   - CN/US 写入 Parquet 前拒绝超过最近已完成交易日的记录。
   - 读取行情、最新收盘价、训练样本、动量扫描和最新指标时过滤未来日期。
   - 这样供应商时钟错误不会污染最新日期或模型训练集。

2. **真实健康检查**
   - 新增 `/health/ready`，同时检查 PostgreSQL、A 股行情湖和美股行情湖。
   - `/health` 仍只代表 Web 进程存活；`/health/ready` 才代表依赖是否可用及行情是否达到应有日期。

3. **行情新鲜度口径拆分**
   - 现有逐股同步状态继续保留。
   - 新增行情湖截至日期、湖内股票数量和权威截至日期，避免 bulk lake 刷新后仍被旧的逐股更新时间误导。

4. **重复点击保护**
   - 风险预警、A 股行情刷新、A 股训练、美股行情刷新在已有同类 running job 时复用已有任务，不再重复启动昂贵计算。

5. **风险闸门已经接入日常链路**
   - CN/US 会生成 `BLOCK / REVIEW / ALLOW` 买入闸门。
   - 暴跌、反抽失败、高离散等环境会限制候选信号进入可执行状态，并在任务中心展示持仓风险。

## 下一阶段优先级

1. 将“行情刷新成功”定义为：目标市场达到应有日期、失败/落后股票数低于阈值，并自动触发补刷，而不是只看 job status。
2. 为每次模型计算记录输入行情日期、训练样本数、缺失率、风险闸门版本；输入不满足条件时明确标记 `not_ready`，禁止日报复用旧模型。
3. 增加滚动 out-of-sample 评测和交易成本后的命中率/盈亏比看板，按市场状态分别评估，避免把暴跌期和正常期混成一个成功率。
4. 对已经存在的历史异常/未来分区运行一次 dry-run 清理，再由任务中心确认后隔离或删除。
5. 把 full-market 刷新、训练、预计算、风险快照、日报发送做成有依赖关系的链路；上游未达标时下游显示 `blocked_by_dependency`。
